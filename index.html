The task

Process a set of 100 full-text biomedical papers (PMC, JATS XML).

Task 1 · Gene and disease extraction

Extract all gene and disease mentions from each paper and output the identified lists, if any.

Task 2 · Gene–disease relationship analysis

For paper i with Ni genes and Mi diseases, evaluate all Ni × Mi candidate pairs. Link a pair if the paper provides evidence of an association, correlation, or causal relationship, yielding a gene–disease bipartite graph per paper.

Our extensions: every link includes its supporting sentence(s) and is labeled as the paper's own finding or background knowledge, while weak evidence is flagged uncertain rather than linked.

Experiment workflow design

Baseline: PubTator3. Models used in the blind tests: Claude Opus 5.5, GPT-6.1 Sol, and GPT-6 Astra.

1Rules as a skill

Define the experiment workflow and decision rules in a standardized skill.md.

2Tune on one paper

Refine the process on 1 paper; hold out 5–10 papers for formal comparison.

3Blind test

Re-run the paper in fresh, unprimed sessions using only the written rules.

4Format verification

A contract validator verifies every quote, character offset, and table.

5Result table

Compare models and rule versions pair by pair.

↺ Feedback loop: disagreements are codified as new rules or boundary cases for the next iteration.

Method development

  • Reviewed existing systems and selected PubTator3 as the comparison baseline.
  • Developed extraction rules on 5 pilot papers, iterating from Skill 1.0 to 1.3, and curated 35 boundary cases to validate rule behavior.
  • Condensed the full rules into a compact decision card to reduce token usage and request turns, confirming that it matches the full rules (110/112 boundary-case decisions agree, stable across 3 runs).
  • Evaluated design variants in a controlled A/B test on a fixed set of 12 papers.
  • Executed the final configuration across all 100 papers and benchmarked accuracy on the expert-annotated BioRED corpus.

Cost-effective optimization

Model: Claude Opus 5.5. Costs reflect CLI-reported list prices, including repair requests.

Each row is measured on its labeled paper set; the 100-paper average includes long papers and all repair requests.

What changed

  • Tracked model behavior across 5 baseline papers before and after each optimization.
  • Built a deterministic toolkit so the model does not need to locate text spans or compute offsets.
  • One request replaces multi-turn agent interaction.
  • Compressed the skill rules (input 20k → 9k tokens) and served them as a cached system prompt.

Output savings

  • Restricted the output schema to essential fields: entities, evidence, and pairs.
  • The model cites sentence numbers rather than copying text; a post-processing script reconstructs quotes and offsets from the paper.
  • Segmented extra-long inputs (conference proceedings) into chunks.

How one request replaces a multi-turn conversation

1Script packs the input

Combines the rules, the paper's numbered blocks and sentences, and the output schema into one prompt.

2Model answers once

Produces a concise structured judgment without tool calls, file reads, or shell commands.

3Script does the rest

The toolkit resolves entity names, computes offsets, populates the gene × disease matrix, and validates the format.

4One repair, only on error

If validation detects errors (e.g., a mismatched citation), the error list is returned to the model once for correction.

Takeaways
  • Compressing the rules into a card preserves the method's behavior. V1 and V2 agree on 97.6% of pairs, while V1 reduces cost by 11%. Most of V2's 11 negative pairs stem from variant-vs-variant comparisons in one paper—a boundary ambiguity logged for the next rule revision.
  • Low thinking is about 2.4× faster and 24% cheaper with 98.5% agreement, but recovers fewer supported relations (56 vs 64) and fewer uncertain flags (15 vs 28).
  • V1 was selected because it identifies the most supported relations at a moderate cost; it was subsequently run on all 100 papers.

Pros

  • Extracts 2.8× more relations, each anchored to its supporting sentence.
  • 81% are supported by full-text content beyond the abstract: body text, tables, and captions.
  • Distinguishes novel study findings from background knowledge and flags weak evidence as uncertain (28 pairs).
  • Separates clinical symptoms from diseases.
  • Processes a Spanish-language paper in which PubTator3 detected no genes.

Cons

  • Requires about $0.30 and 1 minute per paper, whereas PubTator3 is free and precomputed.
  • Misses 12 relations reported by PubTator3: 3 treat a symptom as the disease, 4 were judged too weakly supported, and 5 involve a gene or disease our method did not record.
  • No database IDs (NCBI Gene / MeSH).

Problem: repair requests

Minor output-format deviations initially triggered token-consuming repair requests; the parser was updated to tolerate common syntax slips (fixed).

Why 25 papers have no supported relation

These articles do not investigate gene–disease associations; they represent true negatives rather than missed detections.

  • 8 mention no genes at all (e.g., dialysis timing, adolescent gambling, nanoparticle chemistry).
  • 8 mention genes but no diseases (e.g., fly chromatin, worm oocytes, plant transcriptomes).
  • 9 mention both entities, but no pair is supported by the text (e.g., genes used solely as assay markers or in speculative discussion).

Consistent with this, PubTator3 reported almost no relations in the same 25 papers (one in total).

Result on the BioRED benchmark

BioRED comprises 419 expert-annotated PubMed abstracts containing 1,633 gene–disease relations (every abstract in the corpus that has one). Without training or tuning on BioRED, we ran the same frozen V1 pipeline used for the 100 papers at a cost of $0.056 per abstract.

  • Consistent across Train / Dev / Test splits: F1 is 0.58 / 0.61 / 0.54, with overlapping 95% confidence intervals.
  • Matches PubTator3 precision on 50 test abstracts (0.84 vs 0.83), even though PubTator3 is trained on BioRED. PubTator3's recall is higher (0.65 vs 0.41).
  • Why our recall is lower: 59% of the missed relations are pairs our method evaluated and deliberately classified as not_found or uncertain; the remainder mostly involve symptoms or broad terms (e.g., "tumor", "infection") that BioRED annotates as diseases.

Gene–disease bipartite graphs

The task's final output: one bipartite graph per paper, with genes on one side, diseases on the other, and a link wherever the paper supports a relation. Every link carries its evidence sentence and source label.
