What held up主要发现

  • Reading the full text raised recall on both batches. Claude gained 0.448 [0.299, 0.588] on the locked set; on the further articles it gained 0.518 [0.374, 0.626] on valid articles and 0.322 [0.133, 0.477] with failures counted as empty.在两批文章上，读全文都提高了召回率。Claude 在锁定集上提高 0.448 [0.299, 0.588]；在新增文章上，只算有结果的文章时提高 0.518 [0.374, 0.626]，把失败文章计为空结果时提高 0.322 [0.133, 0.477]。
  • The gain is not specific to LLMs: BioREx also rose by 0.430 and 0.508. It is not automatic either: RENET2 showed no clear gain on either batch.这一提升并非 LLM 独有，BioREx 也分别提高了 0.430 和 0.508；但也不是所有系统都如此，RENET2 在两批文章上都没有明显提升。
  • On valid articles of the further batch, Claude's F1 exceeded RENET2's by 0.262 [0.148, 0.365] and BioREx's by 0.150 [0.104, 0.194]. On the locked set the F1 difference from RENET2 spanned zero (+0.145 [−0.013, 0.291]).在新增文章中有结果的文章上，Claude 的 F1 比 RENET2 高 0.262 [0.148, 0.365]，比 BioREx 高 0.150 [0.104, 0.194]。在锁定集上，Claude 与 RENET2 的 F1 差值的置信区间包含 0（+0.145 [−0.013, 0.291]）。
  • On BioRED Test (100 abstracts), F1 was 0.614 against 0.680 for PubTator3; the paired difference was −0.064 [−0.151, 0.033]. PubTator3's relation model was trained on data including BioRED.在 BioRED Test（100 篇摘要）上，F1 为 0.614，PubTator3 为 0.680，配对差值为 −0.064 [−0.151, 0.033]。PubTator3 的关系模型在训练时用到了 BioRED。

What limits these results主要局限

  • Safety filters left 4 of 30 and 14 of 49 BioTriplex full texts without a Claude result. A blocked article says nothing about extraction ability, but users still lose it: with failures counted as empty, recall on the further articles is 0.632, against 0.848 for BioREx, which runs locally.安全机制使 30 篇中的 4 篇、49 篇中的 14 篇全文没有 Claude 结果。文章被拦截不代表抽取能力差，但用户确实拿不到结果：把失败文章计为空结果时，新增文章的召回率为 0.632，而本地运行的 BioREx 为 0.848。
  • Valid-article results apply only to articles that were not blocked; we do not know what triggers the filters.只算有结果的文章时，结论仅适用于未被拦截的文章；我们不清楚拦截的触发原因。
  • The October decision card lowered recall on BioRED (0.418 vs 0.604 on Dev+Test). This describes that one card; it changed many rules and the length at once, so it is not a general result about detailed prompts.十月的判定卡降低了 BioRED 上的召回率（Dev+Test：0.418 对 0.604）。这一结论只针对这张判定卡：它同时改动了许多规则和提示词长度，不能推广到所有详细提示词。
  • F1 comparisons also depend on entity scope and training text, so they should not be read as better relation judgment.F1 的比较还受实体范围和训练文本影响，不能据此认为关系判断能力更强。

Do the cited sentences support the relation?所引句子真的支持这条关系吗？

Every cited sentence ID resolves, but that does not show support. One annotator judged a stratified sample of 30 pairs per corpus, seeing only the cited sentences, with results weighted to all supported pairs.所有引用的句子编号都能定位到原文，但这不等于句子真的支持该关系。一位标注者在每个语料上检查了 30 条分层抽样的关系，只看所引句子，结果再按全部 supported 关系加权。

The task任务定义

The task covers 100 biomedical papers in PMC JATS XML format.任务涉及 100 篇生物医学论文，输入为 PMC JATS XML 全文。

Task 1 · Gene and disease extraction任务 1 · 基因与疾病实体抽取

Extract all gene and disease mentions from each paper and output the identified entity lists, if any.抽取每篇论文提及的所有基因和疾病名称，并输出实体列表。

Task 2 · Gene–disease relationship analysis任务 2 · 基因–疾病关系分析

For paper i with Ni genes and Mi diseases, evaluate all Ni × Mi candidate pairs. Link a pair if the paper provides evidence of an association, correlation, or causal relationship, yielding a gene–disease bipartite graph per paper.对含 Ni 个基因与 Mi 个疾病的第 i 篇论文，评估全部 Ni × Mi 个候选配对；若原文提供关联、相关或因果关系的证据则建立连边，最终构建每篇论文的基因–疾病二部图。

We also record whether a relation is a finding of the paper or background knowledge. Pairs with weak evidence are marked uncertain and kept separate from the supported links.在原任务之外，我们还标注关系来自本文发现还是背景知识。证据不足的配对记为 uncertain，与 supported 连边分开。

How the rules were developed规则的制定过程

We used PubTator3 as a baseline. Early blind tests included Claude Opus 5.5, GPT-6.1 Sol and GPT-6 Astra.对比基线为 PubTator3。早期盲测使用了 Claude Opus 5.5、GPT-6.1 Sol 和 GPT-6 Astra。

1Write the rules编写规则

Write the extraction steps and decision rules in skill.md.在 skill.md 中写明抽取步骤和判定规则。

2Try pilot papers试跑论文

Refine the rules on pilot papers, then fix the evaluation sets before comparing configurations.用试点论文修改规则，在比较配置前固定评估集。

3Blind test独立盲测

Run the papers in fresh sessions using only the written rules.在全新会话中运行论文，只提供书面规则。

4Format verification格式校验

Check quotes, character offsets and output tables with local code.用本地代码检查引文、字符偏移和输出表格。

5Result table结果对比表

Compare model outputs and rule versions for each gene–disease pair.逐对比较模型输出和规则版本。

Use disagreements to revise the rules or add boundary cases for the next round.把分歧写入规则或边界案例，用于下一轮测试。

From full rules to a decision card从完整规则到判定卡

  • We reviewed existing systems and chose PubTator3 for comparison.调研现有系统后，我们选择 PubTator3 做对比。
  • We developed the rules on 5 pilot papers, from Skill 1.0 to 1.3, and collected 35 boundary cases to check consistency.规则在 5 篇试点论文上从 Skill 1.0 修改到 1.3，另整理了 35 个边界案例检查判定是否一致。
  • We shortened the rules into a decision card to reduce input tokens and interaction turns. It agreed with the full rules on 110/112 boundary-case decisions, with the same result across 3 runs.为减少输入 token 和交互轮次，我们把完整规则压缩成判定卡。在边界案例测试中，110/112 个判定与完整规则相同，3 次运行结果一致。
  • We compared the rule and reasoning configurations on a fixed set of 12 papers.随后在固定的 12 篇论文上比较规则和推理配置。
  • We used the selected V1 configuration for all 100 papers, then evaluated it on BioRED without BioRED-specific training or prompt tuning.选定 V1 后，运行全部 100 篇论文，再用 BioRED 评估；没有针对 BioRED 做训练或提示词调优。

Cost and runtime成本与耗时

These runs used Claude Opus 5.5. Costs are the CLI-reported list prices and include repair requests.以下运行均使用 Claude Opus 5.5，成本按 CLI 报告的官方标价计算，含修复请求。

Reducing model calls减少模型调用

  • We checked model behavior on 5 baseline papers before and after each change.每次修改前后，都在 5 篇基准论文上检查模型行为。
  • Local code locates text spans and calculates character offsets.文本定位和字符偏移计算交给本地代码。
  • Each paper gets one initial request and, if validation fails, at most one repair request.每篇论文先请求一次；校验失败时，至多再请求一次修复。
  • The shorter rules reduced input from 20k to 9k tokens and are reused as a cached system prompt.规则压缩后，输入从 20k 降到 9k tokens，并以缓存的系统提示词复用。

Shorter model responses缩短模型输出

  • The response contains entities, evidence references and gene–disease pairs.模型返回实体、证据引用和基因–疾病配对。
  • The model returns sentence numbers. Local code then retrieves the original quotes and their character offsets.模型只返回句子编号，本地代码再取出原文并计算字符偏移。
  • Very long documents, such as conference proceedings, are split into chunks.会议论文集等超长文献分块处理。

Extraction steps抽取步骤

1Prepare the prompt准备输入

Put the rules, numbered paragraphs and sentences, and response schema in one prompt.将规则、编号后的段落和句子、输出格式放入同一条提示词。

2Run the model模型抽取

Return structured judgments without tool calls, file reads or shell commands.模型直接返回结构化判定，不调用工具、读文件或执行命令。

3Recover source spans回填原文

Locate mentions, calculate offsets, fill the gene × disease matrix and check the output format.本地代码定位实体提及、计算偏移、补全基因 × 疾病矩阵，并检查格式。

4Repair if needed按需修复

Send validation errors, such as a mismatched citation, back to the model for one repair attempt.如有引文不匹配等校验错误，将错误发回模型，尝试修复一次。

  • Compared with V1, low reasoning effort used about 60% less time and 32% less money, including repairs. Limitations局限性

  • For these 12 papers, the mean was $0.38 and 70 s per paper including repairs ($0.30 for the first request). PubTator3 annotations are free to query.这 12 篇论文平均每篇花费 $0.38、耗时 70 秒，包含修复；仅首次请求为 $0.30。PubTator3 的预计算标注可免费查询。

Next steps下一步

Stronger annotation更可靠的标注

Repeat the citation check after a delay, add an independent second annotator, and judge the status labels on larger samples.隔一段时间重做引用检查，加入独立的第二位标注者，并在更大样本上评估状态标签。

Safety-filter failures安全机制拦截

Report suspected false positives to the provider, replicate whole batches with a second model, and compare systems with entity scope held fixed.向服务商反馈疑似误判，用另一模型对整批文章做复现，并在固定实体范围后比较各系统。
