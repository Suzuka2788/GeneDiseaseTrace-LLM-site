The task任务

Process a set of 100 full-text biomedical papers (PMC, JATS XML).处理 100 篇生物医学全文论文（PMC，JATS XML）。

Task 1 · Gene and disease extraction任务 1 · 基因与疾病抽取

Extract all gene and disease mentions from each paper and output the identified lists, if any.从每篇论文中抽取提到的所有基因和疾病，输出识别出的列表（如有）。

Task 2 · Gene–disease relationship analysis任务 2 · 基因–疾病关系分析

For paper i with Ni genes and Mi diseases, evaluate all Ni × Mi candidate pairs. Link a pair if the paper provides evidence of an association, correlation, or causal relationship, yielding a gene–disease bipartite graph per paper.对含 Ni 个基因、Mi 个疾病的第 i 篇论文，评估全部 Ni × Mi 个候选配对。若论文提供了关联、相关或因果关系的证据，就把这一对连起来，最终得到每篇论文的基因–疾病二部图。

Our extensions: every link includes its supporting sentence(s) and is labeled as the paper's own finding or background knowledge, while weak evidence is flagged uncertain rather than linked.我们的扩展：每条连线都附有支撑它的原文句子，并标明是论文自身的发现还是背景知识；证据不足的配对标为 uncertain，不连线。

Experiment workflow design实验流程设计

Baseline: PubTator3. Models used in the blind tests: Claude Opus 5.5, GPT-6.1 Sol, and GPT-6 Astra.基线：PubTator3。盲测中使用的模型：Claude Opus 5.5、GPT-6.1 Sol 和 GPT-6 Astra。

1Rules as a skill规则写成 skill

Define the experiment workflow and decision rules in a standardized skill.md.用标准化的 skill.md 定义实验流程和判定规则。

2Tune on one paper在一篇论文上调试

Refine the process on 1 paper; hold out 5–10 papers for formal comparison.在 1 篇论文上打磨流程；另留 5–10 篇用于正式对比。

3Blind test盲测

Re-run the paper in fresh, unprimed sessions using only the written rules.在没有任何先验信息的新会话中，只凭书面规则重做这篇论文。

4Format verification格式校验

A contract validator verifies every quote, character offset, and table.契约校验器逐一核对每条引文、字符位置和表格。

5Result table结果表

Compare models and rule versions pair by pair.逐对比较不同模型和规则版本。

↺ Feedback loop: disagreements are codified as new rules or boundary cases for the next iteration.↺ 反馈循环：出现的分歧被整理成新规则或边界案例，进入下一轮迭代。

Method development方法构建

  • Reviewed existing systems and selected PubTator3 as the comparison baseline.调研现有系统，选定 PubTator3 作为对比基线。
  • Developed extraction rules on 5 pilot papers, iterating from Skill 1.0 to 1.3, and curated 35 boundary cases to validate rule behavior.在 5 篇试点论文上制定抽取规则，从 Skill 1.0 迭代到 1.3，并整理出 35 个边界案例来检验规则行为。
  • Condensed the full rules into a compact decision card to reduce token usage and request turns, confirming that it matches the full rules (110/112 boundary-case decisions agree, stable across 3 runs).把完整规则压缩成一张精简的判定卡，以减少 token 用量和请求轮数，并确认它与完整规则一致（110/112 个边界案例判定相同，3 次运行结果稳定）。
  • Evaluated design variants in a controlled A/B test on a fixed set of 12 papers.在固定的 12 篇论文上用对照 A/B 测试比较不同设计。
  • Executed the final configuration across all 100 papers and benchmarked accuracy on the expert-annotated BioRED corpus.用最终配置跑完全部 100 篇论文，并在专家标注的 BioRED 语料上测量准确率。

Cost-effective optimization成本优化

Model: Claude Opus 5.5. Costs reflect CLI-reported list prices, including repair requests.模型：Claude Opus 5.5。成本为 CLI 报告的标价，包含修正请求。

Each row is measured on its labeled paper set; the 100-paper average includes long papers and all repair requests.每一行都在其标注的论文集上测得；100 篇的平均值包含长论文和全部修正请求。

What changed做了哪些优化

  • Tracked model behavior across 5 baseline papers before and after each optimization.在 5 篇基准论文上跟踪每次优化前后的模型行为。
  • Built a deterministic toolkit so the model does not need to locate text spans or compute offsets.构建确定性的工具包，模型不必自己定位文本或计算字符位置。
  • One request replaces multi-turn agent interaction.一次请求取代多轮 agent 交互。
  • Compressed the skill rules (input 20k → 9k tokens) and served them as a cached system prompt.压缩 skill 规则（输入 20k → 9k tokens），并作为缓存的系统提示词发送。

Output savings输出精简

  • Restricted the output schema to essential fields: entities, evidence, and pairs.输出格式只保留必要字段：实体、证据和配对。
  • The model cites sentence numbers rather than copying text; a post-processing script reconstructs quotes and offsets from the paper.模型引用句子编号而不复制原文；后处理脚本从论文中重建引文和字符位置。
  • Segmented extra-long inputs (conference proceedings) into chunks.超长输入（会议论文集）分段发送。

How one request replaces a multi-turn conversation一次请求如何取代多轮对话

1Script packs the input脚本打包输入

Combines the rules, the paper's numbered blocks and sentences, and the output schema into one prompt.把规则、论文的编号文本块与句子，以及输出格式合成一条提示词。

2Model answers once模型只回答一次

Produces a concise structured judgment without tool calls, file reads, or shell commands.输出一份简洁的结构化判断，不调用工具、不读文件、不执行命令。

3Script does the rest脚本完成其余工作

The toolkit resolves entity names, computes offsets, populates the gene × disease matrix, and validates the format.工具包定位实体名称、计算字符位置、补全基因 × 疾病矩阵并校验格式。

4One repair, only on error仅在出错时修正一次

If validation detects errors (e.g., a mismatched citation), the error list is returned to the model once for correction.若校验发现错误（例如引文对不上），把错误清单发回模型修正一次。

Takeaways结论
  • Compressing the rules into a card preserves the method's behavior. V1 and V2 agree on 97.6% of pairs, while V1 reduces cost by 11%. Most of V2's 11 negative pairs stem from variant-vs-variant comparisons in one paper—a boundary ambiguity logged for the next rule revision.把规则压缩成判定卡不改变方法的行为。V1 与 V2 在 97.6% 的配对上一致，V1 便宜 11%。V2 的 11 个 negative 配对大多来自同一篇论文中"变异与变异"的比较，这是规则的一个边界模糊之处，已记录，待下一版规则处理。
  • Low thinking is about 2.4× faster and 24% cheaper with 98.5% agreement, but recovers fewer supported relations (56 vs 64) and fewer uncertain flags (15 vs 28).低推理强度约快 2.4 倍、便宜 24%，一致率 98.5%，但 supported 关系更少（56 对 64），uncertain 标记也更少（15 对 28）。
  • V1 was selected because it identifies the most supported relations at a moderate cost; it was subsequently run on all 100 papers.最终选择 V1：它以中等成本找到最多的 supported 关系，随后用于全部 100 篇论文。

Pros优点

  • Extracts 2.8× more relations, each anchored to its supporting sentence.抽取的关系多 2.8 倍，每条都对应支撑它的句子。
  • 81% are supported by full-text content beyond the abstract: body text, tables, and captions.81% 的关系依据摘要以外的全文内容：正文、表格和图注。
  • Distinguishes novel study findings from background knowledge and flags weak evidence as uncertain (28 pairs).区分研究本身的新发现与背景知识，并把证据不足的配对标为 uncertain（28 对）。
  • Separates clinical symptoms from diseases.把临床症状与疾病区分开。
  • Processes a Spanish-language paper in which PubTator3 detected no genes.能处理一篇西班牙语论文，而 PubTator3 在其中没有识别出任何基因。

Cons缺点

Problem: repair requests问题：修正请求

Minor output-format deviations initially triggered token-consuming repair requests; the parser was updated to tolerate common syntax slips (fixed).输出格式的小偏差起初会触发消耗 token 的修正请求；已更新解析器，容忍常见的格式小错（已修复）。

Why 25 papers have no supported relation为什么 25 篇没有 supported 关系

These articles do not investigate gene–disease associations; they represent true negatives rather than missed detections.这些论文本身不研究基因–疾病关联：它们是真阴性，而不是漏判。

  • 8 mention no genes at all (e.g., dialysis timing, adolescent gambling, nanoparticle chemistry).8 篇完全没有提到基因（例如透析开始时机、青少年赌博、纳米颗粒化学）。
  • 8 mention genes but no diseases (e.g., fly chromatin, worm oocytes, plant transcriptomes).8 篇提到了基因但没有疾病（例如果蝇染色质、线虫卵母细胞、植物转录组）。
  • 9 mention both entities, but no pair is supported by the text (e.g., genes used solely as assay markers or in speculative discussion).9 篇两者都有，但文中没有任何一对得到支持（例如基因只作为检测指标，或只出现在推测性讨论中）。

Consistent with this, PubTator3 reported almost no relations in the same 25 papers (one in total).与此一致，PubTator3 在这 25 篇论文中也几乎没有预测出关系（合计 1 条）。

Result on the BioRED benchmarkBioRED 基准上的结果

BioRED comprises 419 expert-annotated PubMed abstracts containing 1,633 gene–disease relations (every abstract in the corpus that has one). Without training or tuning on BioRED, we ran the same frozen V1 pipeline used for the 100 papers at a cost of $0.056 per abstract.BioRED 中有 419 篇专家标注的 PubMed 摘要，共 1,633 条基因–疾病关系（即语料中所有含此类关系的摘要）。我们没有在 BioRED 上做任何训练或调整，直接使用跑 100 篇论文时冻结的 V1，每篇摘要成本 $0.056。
